# 设计：测试协议、指标与评分

## 1. 测试协议

每个节点执行 `R` 轮（默认 5，推荐 10）独立的代理请求：

```
GET http://<controller>/proxies/{name}/delay?url=<test-url>&timeout=<ms>
```

- 请求经过目标节点，返回该次请求的毫秒延迟；
- 失败（超时、DNS、TLS、节点拒绝）记为失败；
- 不做失败重试：失败率本身就是稳定性信号；
- 节点之间并发，节点内部串行，避免同一节点自竞争。

默认测试 URL：`https://www.gstatic.com/generate_204`。可换成 `https://www.cloudflare.com/cdn-cgi/trace` 或自定义。

## 2. 指标

| 指标 | 定义 |
|---|---|
| `success` | 成功轮数 |
| `total` | 总轮数 |
| `min_ms` | 成功轮的最小值 |
| `median_ms` | P50 |
| `p90_ms` | P90，反映尾部延迟 |
| `max_ms` | 最大值（仅供参考，容易被单次尖刺影响） |
| `jitter_ms` | `P90 - P50`，比 `max-min` 更抗单次尖刺 |
| `score` | 综合评分，见下 |

## 3. 评分

```
successRate   = success / total
latencyScore  = clamp(1 - (p90 - 100) / 900, 0, 1)
stabilityScore= clamp(1 - jitter / 500, 0, 1)
score         = 0.5 * successRate + 0.3 * latencyScore + 0.2 * stabilityScore
```

解释：

- 100ms 的 P90 得满分，1000ms 得 0；
- 0ms 抖动得满分，500ms 抖动得 0；
- 成功率权重最高：能用比快更重要；
- 成功率 `< 0.8` 的节点额外乘 `successRate`，避免“偶尔能通”的节点排前面。

示例：

| 节点 | 成功率 | P90 | 抖动 | 分数 |
|---|---|---|---|---|
| A | 10/10 | 120ms | 20ms | 0.5 + 0.29 + 0.19 = 0.98 |
| B | 10/10 | 300ms | 120ms | 0.5 + 0.23 + 0.15 = 0.88 |
| C | 6/10 | 180ms | 60ms | (0.5*0.6 + 0.27 + 0.18) * 0.6 = 0.45 |

## 4. 自动选择（核心）

目标不是“每次选最低延迟”，而是“当前节点明显变差时才切，并且切得可解释、可回滚”。

### 组与候选

- 只管理 `Selector` 组，**永不自动选择 `GLOBAL`**；
- 优先显式配置的组；未配置时只按通用名称（节点选择 / Proxy / Selector）排序选择，不把个人机场名写进产品；
- 只测试该组的**直接可测节点**；嵌套组和 DIRECT/REJECT 跳过；
- 组内没有直接节点时给出清晰错误，**不回退到全量代理**，避免切到管理组之外。

### 决策

```
candidate.successRate >= 0.8
and candidate.score > current.score * (1 + margin)
and 连续 confirm 轮成立
=> switch
```

- `margin` 默认 20%，`confirm` 默认 2 轮，均可在设置页调整；
- 当前节点不达标时立即切到最佳达标节点；
- 当前已经是最佳时保持不动；
- 所有节点不达标时，用 `DIRECT` 做本地基线：DIRECT 也失败则提示网络/测试 URL 问题，而不是误判节点全挂；
- 结果带置信度（轮数 <3 低、3–4 中、≥5 高）。

### 切换事务

1. 记录 before 指标、候选、原因码、置信度、耗时；
2. 调用切换；
3. 等待控制器生效，校验当前节点；
4. 对新节点做一次真实延迟验证；
5. 任一步失败都尝试回滚，并记录 `rollback_attempted` / `rollback_ok`；
6. 事件写入历史；GUI/Web 在仪表盘显示“最近自动选择”和原因，History 显示完整事务。

### 常驻

- 自动优化开关、间隔、margin、confirm、min-success 保存到 settings；
- 页面重载后若开关为开且控制口可用，自动恢复 daemon；
- 切换环境时停止旧 daemon，按新环境决定是否恢复；
- 手动测速与自动优化互斥，避免两套决策同时操作同一个组。

## 4.1 多订阅联合测速

FlClash / Clash Verge 的 Clash 控制口只暴露**当前激活配置**；未激活订阅不在 `/proxies` 或 `/providers/proxies` 中。因此“获取客户端里的全部订阅”必须分两条路：

- 激活配置：通过控制口读取，可测试、可切换；
- 未激活 profile：只读客户端本地的 profile YAML（FlClash `profiles/*.yaml`、Clash Verge profiles 目录、Mihomo 配置），合并后用临时 mihomo sidecar 测速。

联合测速的行为：

1. 扫描已知客户端的 profile 文件，去重；
2. 每个 profile 读取 `proxies`，只保留可测试节点；
3. 节点同名时加订阅来源后缀，避免测速/展示冲突；
4. 用同一 URL、轮数、并发和超时，在同一个 sidecar 中测试；
5. 结果带来源标签，给跨订阅总排名；
6. **只推荐，不自动切换未激活订阅**：客户端没有公开 API 让 NodePulse 切换 profile，强行改数据库/配置不可接受。

如果没有本地 profile 文件，则回退到当前控制口的所有直接节点；如果只有激活订阅，行为与普通全量测速一致。FlClash 的 profile 文件本身不保存订阅显示名，标签会回退到该 profile 的首个分组名。

## 5. 驻留、通知与开机自启

自动选择只有在后台持续运行时才有价值，但常驻能力不能变成打扰。

- 桌面版关闭窗口时默认隐藏到系统托盘，自动选择继续运行；托盘菜单提供“打开面板”“开机启动”“退出”。
- 开机自启**默认关闭**，由用户显式开启；启动时隐藏窗口，只驻留托盘。
- 系统通知只发送“已切换”“已回滚”“检查失败”三类事件，不发送每轮检查；窗口在前台可见时不重复通知。
- 通知内容只包含结论、节点名和原因，不包含 secret、订阅 URL 或其他凭据。
- Web 版不提供托盘和桌面通知；这些能力只在桌面 GUI 中存在。

理由：用户需要知道“自动选择动了我的连接”，但不需要每 5 分钟收到一条“一切正常”。

## 6. 导出影响预览

导出会过滤节点并可能让分组变空，因此默认导出前必须先解释影响：

- 显示保留/排除节点数、被排除节点示例；
- 显示哪些分组会失去成员、哪些分组会退化为 `DIRECT`；
- 显示规则、rule-providers、DNS、TUN 是否保留；
- 默认“保留原规则/分组”；只有明确选择最小配置时才提示规则、DNS/TUN 和分组将被替换；
- 用户确认后才写入文件，避免“点了导出才发现规则没了”。

## 7. 备份与迁移

安全边界按“覆盖前先留底”实现，不做完整版本库：

- 设置文件每次内容变化前自动备份，保留最近 20 份，权限 0600；
- 导出配置覆盖已有文件前自动备份该文件；
- 设置支持手动导出/导入，用于换机迁移；导入会先备份当前设置；
- 备份目录固定为 `~/.local/share/nodepulse/backups/`，不写入项目目录；
- 设置备份包含 secret，UI 必须明确提示，文件权限保持 0600。

## 8. 结果持久化

测速结果是自动选择和导出的依据，不能因为重启 GUI 就消失：

- GUI 与 Web 使用同一份结果文件结构（生成时间、测试 URL、轮数、配置路径、结果）；
- GUI 启动时恢复结果，但仅当保存的配置路径与当前环境一致；
- 切换环境或清除结果时删除持久化文件；
- 写入使用临时文件 + rename，避免半截 JSON 破坏下次启动。

## 9. 跨平台打包

- Linux：本地构建 `.deb` / AppImage，使用 `production,webkit2_41` 标签；
- Windows：CI 使用 Wails 构建，产出 zip；暂不做 MSI；
- macOS：CI 构建 `.app`，打包为 zip；签名和公证需要发布者证书，单独处理；
- 本地不伪造跨平台构建结果；Windows/macOS 以 CI 产物为准。

## 10. 导出格式

`export` 默认生成可日用的完整 Clash 配置：

- 保留原 `rules`、`proxy-groups`、`dns`、`tun`、`rule-providers` 等字段；
- `proxies` 只保留通过阈值的节点；
- 每个组的成员过滤为稳定节点或仍存在的子组；组为空时回退 `DIRECT`；
- 追加 `NodePulse`（url-test）组，方便直接选择；
- 清理 `external-controller` 和 `secret`，避免导入后覆盖客户端控制口；
- `--minimal` 才会生成只含 `NodePulse` + `MATCH,NodePulse` 的最小配置。

节点参数原样保留（包括 Reality、WS、Hysteria2 等字段），避免导出后不可用。

## 12. 边界情况
- **信息伪节点**：名字包含“剩余流量 / 套餐到期 / 流量重置 / 官网”等，默认跳过；
- **重复节点**：同名或同 `server:port:type` 的节点在排名中标注，导出时去重；
- **DNS 失败**：直接计为失败，不尝试修复（客户端侧 DNS 问题另算）；
- **节点改名**：结果按 name 关联，导出前校验节点仍存在；
- **订阅更新**：结果文件带时间戳，导出时提示是否过期（Phase 2）。

## 13. 首启环境检查

不做多步向导，只把“现在能不能用”讲清楚：

- 检查控制口、订阅路径、mihomo、Selector 组；
- 每项给出 `ok / warn / error` 和一句可执行建议；
- 设置页“环境检查”卡片可手动重新检查；
- 控制口不可达时不影响本地订阅 + sidecar 模式；
- 检查只读，不修改用户配置。

理由：首启失败通常不是功能缺失，而是用户不知道缺哪一项。一个可操作的检查列表比引导流程更短。

## 14. daemon 跨进程互斥

同一台机器上 GUI、Web 和 CLI 都可能启动自动选择。两个 daemon 同时操作一个控制口会互相覆盖切换结果，因此必须单写者：

- 锁文件：`~/.local/share/nodepulse/daemon.lock`；
- 获取失败时返回明确提示“另一个 NodePulse 实例正在运行自动选择”，不静默降级；
- 锁持有者退出时删除锁文件；
- 进程崩溃留下锁文件时，通过 PID 存活检查清理，避免永久占锁；
- 测试和自定义数据目录可以覆盖锁路径。

## 15. 订阅拉取边界

订阅 URL 是用户主动输入的，但下载仍要有边界：

- 只允许 `http` / `https`，拒绝 URL 内嵌用户名密码；
- 限制重定向次数、超时和响应体大小（10 MiB）；
- 拒绝链路本地/云元数据地址（如 `169.254.0.0/16`），避免被诱导访问元数据服务；
- **不**一刀切禁止 RFC1918/loopback：用户可能自建订阅或局域网服务；
- 每次重定向都重新校验目标，而不是只校验首个 URL。
